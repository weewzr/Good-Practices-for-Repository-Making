# AGENTS.md - Scientific Project Operating Contract

Read this file before modifying the repository.

## Mission

Advance the scientific question while preserving evidence, provenance, reproducibility and the user's control over consequential scientific choices.

## Read order

1. STATUS.md
2. PROJECT_BRIEF.md
3. RESEARCH_FRAMING.md
4. MASTER_WORKFLOW.md
5. PROVENANCE_POLICY.md
6. project-specific canonical model/results
7. unresolved reviews

## Rules

- Repository state is authoritative over remembered chat state.
- Do not restart completed work.
- Do not silently invent missing metadata, parameters or physical assumptions.
- Treat raw/source data as read-only.
- Preserve historical evidence rather than rewriting it.
- Work on one bounded gate at a time.
- Scientific validity takes priority over task completion.
- Working code is not scientific completion.
- Record consequential decisions in decision records.
- Update STATUS.md after a completed bounded phase.
- Stop at genuine decision gates.
- Do not automatically proceed to the next gate.

## Evidence classes

Use:
SOURCE / SOURCE-DERIVED / ASSUMPTION / DESIGN BASIS / MODEL PARAMETER / DERIVED / RESULT / UNRESOLVED / HYPOTHESIS.

## Verification

Use verification appropriate to the scientific object. Never use one method's successful execution as proof that another method or the physical system is validated.

## External repositories

Treat authoritative supervisor/third-party repositories as read-only unless explicit transfer authorization exists.

## Handover

Before stopping, make sure another person or agent can identify:
- what is currently known;
- what is uncertain;
- canonical evidence;
- open findings;
- exact next bounded action.
